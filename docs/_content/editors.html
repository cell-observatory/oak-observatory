OAK ships two editor extensions — the VS Code extension and the JetBrains plugin (IntelliJ, PyCharm, WebStorm, and the rest). Both are thin renderers over the CLI, so every number matches the terminal app — one record, rendered in whichever editor you live in. The demo below is the same self-playing session as the homepage — an agent editing a Python pipeline while the observatory fills in around it; pause or step through it with the controls.

The Observatory Traces sidebar, inline review, and the Dashboards dock — all live, filling in as the agent works.

What's inside

  • The Overview panel — the master-detail board: Sessions, Workers, Processes, Tasks, and Workflows, with the change map scoped by selection.
  • The Traces sidebar — every captured edit in the project tree, grouped by file, with per-row Keep and Undo.
  • Inline review — pending edits in the editor itself, and the review bar that carries the verbs.
  • The stacked diff view — Open all in editor pages through the pending work in one tab, each diff with its own Keep and Undo.
  • The Timeline panel — Feed, Prompts, Observations and Actions in one panel.

Two editors, one setting

Which review surface appears is a setting, spelled the same way where the editors overlap. JetBrains IDEs expose a floating-toolbar layer, so the review controls sit as a floating toolbar over the editor. VS Code exposes no floating-widget API, so it uses a compact bar built on a comment thread, plus a review bubble one click away. A file with pending edits carries a count badge in the editor's own project tree — and on the editor tab in VS Code.

Start in one, finish in the other

Because both render the same store through the CLI, a review can start in VS Code and finish in JetBrains, or in the terminal — every surface agrees on the same numbers and the same decisions.

Review a session on another machine

Select a session from a saved machine (oak machine list --json). Open all in editor opens a stacked review in this window, ten changes per page. Each page is read in one bounded call to the saved machine; Keep, Undo and Redo run there and refresh the block. A file that no longer exists still shows its recorded change. The side-by-side switch uses a verified mount when available and the recorded before/after otherwise. Open on <machine> and the filename first use a matching mounted share for editing. OAK matches Linux or macOS mount tables against the saved host, its home share, or a network share mounted on both machines. A local file with the same pathname is not enough. The mounted files are editable, with highlights, inline review controls and File History. Keep, Undo, Redo and Resolve still run with --machine; OAK refreshes after each action because SMB notifications can lag.

Without a matching mount, VS Code and Cursor open a new Remote-SSH window at the session’s workspace, using the saved machine’s SSH target. JetBrains uses Gateway / Remote Development over SSH. OAK writes a request on that machine, valid for ten minutes and consumed once by the remote editor, to select the session and open the edit or file. The remote window uses its real files and normal OAK highlights, inlays and Open all view.

If OAK is missing on the remote editor server, the editor offers to run oak install-extensions --machine <label> there. Connect once first if the editor has not installed its server. JetBrains needs an installed remote IDE to build its documented Gateway connect link; if it cannot build the link, or Gateway does not open, the dialog gives the SSH target, workspace and steps for File → Remote Development → SSH → New Connection. After an expired request, select the session in that window’s OAK.

This window still lists remote edits, prompt scopes, counts and history, and runs review actions on their machine. Diff is a separate action: it opens the editor’s before/after viewer using contents read from that machine, with a patch fallback for older CLI versions. Replies remain in Timeline/Feed, quotes and review comments; Review has no reply box.

Both editors support task decisions, conversation search, keyboard edit/file navigation and replies in Timeline/Feed for sessions on saved machines. See remote review controls.

Open workspace window

In Observatory’s Sessions list or a session picker, choose Open workspace window (the window button in VS Code/Cursor; right-click the row in JetBrains). The session’s folder opens in its own editor window. Saved machines use Remote-SSH in VS Code/Cursor or Gateway in JetBrains, with SSH instructions if Gateway cannot open. A missing folder or a session with no workspace is refused. One action opens one workspace.

The window pins the session and opens its pending changes in the stacked editor, ten per page. With nothing pending, OAK says so and opens no empty tab. It reveals Review, File History and the Observatory Timeline, and focuses the Overview with Sessions, Workers, Processes, Tasks and Workflows side by side and the change map beside them. Your saved view placements stay in place. A terminal named OAK runs oak; an existing OAK terminal is reused. JetBrains needs its Terminal plugin for that terminal. An already-open workspace receives the same request without restarting the editor; a request is used once and expires after ten minutes.

Use one window per machine and workspace instead of combining mounted folders in a multi-root workspace. OAK, git and file watching then run on the machine that owns the files, and a stalled extension host affects only that window.
