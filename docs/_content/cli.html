Every view the editors render is a CLI command underneath. The oak command is the complete backend — usable on its own, scriptable, and the single source of truth both editors thin-render. Add --json to almost any command to get its payload as data.

Setup

CommandWhat it does
oak initInstall the capture hooks in your user settings; --project writes them into this repository's .claude/settings.json instead.
oak install-extensionsSide-load the VS Code + JetBrains extensions. The VS Code one then self-updates; JetBrains updates once you add its plugin repository (the command prints the step).
oak statusConfirm the hook is installed and show what's captured.
oak doctorDiagnose capture and configuration problems.
oak statuslineInstall or refresh the bundled status line with the usage bars (a bash script that needs jq).
oak uninstallRemove the capture hooks from every settings file OAK recorded writing; oak init --repair replaces duplicated hook entries instead.

Viewing the record

CommandWhat it does
oak · oak tuiThe full terminal dashboard. --once prints one frame.
oak sessionsList this machine’s sessions, grouped by workspace, leaving out sessions in which nothing happened. With --json, each session lists its workers still at it (activeWorkers). --json --machine <label> lists a saved machine’s sessions: from the local database when oak sync read that machine in the last ten minutes and nothing there may be running (no session active in the last two hours, as its records and the files that run saw say, no hand raised in the last day still up), saying how fresh (fromIndex, syncedAt, publishedAt), and over SSH otherwise. --json --synced adds every other machine’s sessions the local database holds from oak sync’s records, by machine (machines), each with when oak sync last read it (syncedAt).
oak titlesThe Remote Control titles read from claude.ai, which name sessions the way the Claude app does: when they were last read and how many are cached. --refresh reads now; --off stops the automatic read and deletes the cache; --on resumes it.
oak inboxEvery session waiting on you, most urgent first — permission prompts with their tool, questions with their options, input waits, then finished turns, after oak sync’s open conflicts, each with the oak sync resolve command that deletes its copy. The other machines’ raised hands are listed with this machine’s, as their records brought them, each with its machine and when oak sync brought it; --json adds that machine’s id and label and how fresh the hand is. --next names the one to jump to, among this machine’s sessions.
oak searchEvery conversation on this machine, ranked — the asks you typed and the answers you got, across sessions and workspaces. Every word must appear; a hit in the ask outranks one in the answer. Codex Auto-review threads are left out. --per-session keeps each session's best match, before --limit applies; --json reports in matched how many matches there were before the limit. --machine <label> searches a saved machine's conversations: in its records here when oak sync read it in the last ten minutes, and there over SSH otherwise.
oak queryAsk this machine’s local database in JSON: sessions (every machine’s the database holds), edits, files, prompts, search (asks and answers, ranked, an ask over its answer), workers, delegated, findings (what agents filed with oak finding), sync, notes (plans, memories and skills), usage (tokens in a window by machine, model, session, day, agent or account, each message once), readings (the shares each machine read of the account’s windows, and the Claude account’s answers on its five-hour limit) or schema, each with --<param> <value> filters (--since 7d, --text <words>, --status pending). The rows of sessions, edits, prompts, search, workers and notes name their machine by id (machine), which a query’s own --machine takes, as it takes self and the label a saved machine has here, and by this machine’s name for it (machine_label): for a saved machine, the label the other commands’ --machine takes. Any other name is refused with bad_param. files lists a file once by its repository and its path within it, every clone and folder together; edits --path takes that path, with --project, or an absolute path in this machine’s clone, and refuses one outside every project with bad_param. Sessions whose files are gone are kept in the database, archived, and listed only with --archived or --all, marked with when and why. oak query sql "<SELECT …>" runs one read-only statement in a child process stopped at --timeout <ms>. --arrays returns rows as arrays, --table prints each row for reading, oak query --serve answers one JSON request per line. Exit status 2 means the query cannot run, 3 that there is no database here, 124 that raw SQL ran past its deadline. Database & sync has worked examples.
oak notifyDesktop notifications for raised hands: --watch announces every hand raised on this machine from a plain terminal, and every hand the other machines’ records bring, naming the machine, each once per machine; --message pops one to check the plumbing.
oak prompts · oak tasklogThe prompt and task groupings.
oak changemapThe change map for a scope.
oak observations · oak actionsThe Observations and Actions surfaces.
oak stats · oak metrics · oak usageVitals, derived numbers, and token usage. oak usage --breakdown splits tokens, cache reads and estimated dollars by week, bill-cycle month, model or session, for Claude and Codex; the dollars price token counts at today’s API list prices, carry a ~, and are never a bill. oak usage --window 5h|week|bill|month|day|all --by machine|model|session|day|agent|account answers from the local database, counting each message once across every machine whose usage it holds; by session, a session counts every agent it started, with its own turns on the line under it (--json: the oak query usage answer).
oak integrityReport capture gaps and unsafe history in a session’s records, without rewriting them.
oak fleet · oak feedThe fleet board and a live feed. oak fleet --json lists named Claude Code and Codex workers from herdr, OAK-started agents and recent repository worktrees, including the reviewed session’s subagents. --machine reads the owning machine; oak sessions --json --workers combines the session listing and workers. oak siblings --repo retains the path-only sibling digest and other machines’ repository sessions from the local database.
oak risk · oak egressThe two audits.

Reviewing

CommandWhat it does
oak keep · oak undoKeep or undo the review unit an edit belongs to; --ids acts on single edits, --ids … --units widens each to its unit, and --all acts on a scope.
oak resolveAccept every pending edit in a session and clear its records.
oak task-keep · oak task-undo · oak task-clearAct on a task's strict span. Add --machine <label> to run on its saved machine, including task-clear --completed.
oak redo --from-promptRe-apply undone edits from a prompt onward.
oak undo … --forceRestore the whole file when a surgical undo conflicts.
oak undo --ids … --record-only · oak redo --ids … --record-onlyRecord what an undo or redo already did on disk, without touching the files. OAK prints this command, with the edit ids, when the store stays busy after an undo or redo has changed the files.

Driving and housekeeping

CommandWhat it does
oak agent setup [--yes] [--check] [--json] [--project] [--remove]Preview and install managed delegation guidance, defaults and permissions; check or remove it. User-edited content stays intact. See setup.
oak agent start --kind claude|codexStart a native agent in herdr.
oak agent start --kind claude|codex --brief <file> [--machine <label>]Add --worktree [<base>] for a new worktree and repeat --writable-root <dir> for Codex write access. Start an agent from a brief in its own herdr tab, labelled from the brief’s title, here or on a saved machine, and record it (see The workflow).
oak agent start … --brief <file> --after <id…> [--after-any]Record the agent immediately as queued, waiting on the named ids. A detached OAK job starts it after every dependency is done, even after the queuing terminal closes. Gone is a failed dependency; --after-any accepts it. Unknown ids and cycles are refused. oak agent close <id> cancels a queued start. Dependencies on saved machines use their existing records in the database, or SSH when needed.
oak agent tell <id…> <text> [--json]
oak agent tell <id…> --file <path> [--json]		Send follow-up scope to running Claude Code or Codex agents, through each agent’s own chatbox, over SSH for saved machines. A busy agent queues the message in its native client. Every recipient is checked before sending; gone, done, closed, queued or missing agents are refused. Text is passed literally; tabs and newlines are accepted, other control characters are refused. Use -- before literal text that is a flag. The native transcript supplies Prompts and Feed; OAK also records the sender, text and time in the delegated record. oak agent list --json includes lastMessageMs (null before the first message) and messages. If delivery loses its acknowledgement, check the named pane before retrying.
oak agent list [--all] [--json]Every agent started from a brief, with OAK’s own state (queued, starting, working, waiting, blocked, errored, done, gone) and when it began, its machine and tab, its tokens and cost, its workers, and recorded worktree change and merge state.
oak agent wait <id…> --until done|blocked|anyReturn once every agent is done or gone, one is blocked or errored, or one is neither starting nor working nor queued; 124 at --timeout.
oak agent close <id…> [--remove-worktree]Close each agent’s herdr tab, on its machine, and keep its row. --remove-worktree removes only a clean, merged worktree.
oak attach [machine]Hand this terminal to herdr, here or on a saved machine over SSH, the way tmux attach does.
oak prompt --session <id> --text "…"Submit text to a session’s live herdr pane. Without one, the draft stays on the clipboard and is printed, and the command exits with status 75.
oak comment · oak quoteDraft review comments on an edit’s lines, or a quote of the agent’s last reply, as one prompt. Nothing is sent until you ask: oak comment send and oak quote --send submit through herdr, and a failed send keeps the draft and exits with status 75 (oak comment send with nothing to send exits 0).
oak processes [--session <id>] [--machine <label>] [--json]List the session’s background shells and its Claude workers’ shells, running first, with command, state, runtime, exit code and the recorded output path. --id <id> reads one tail. A worker shell uses <worker-id>:<shell-id>.
oak processes --follow <id> [--session <id>] [--machine <label>] [--json]Follow the selected shell’s output until recorded completion or Ctrl+C. The first read shows up to 16 KiB from the end; later text output contains new bytes. A burst beyond that window is reported as skipped. --json emits one snapshot per line, including process, outputTail, outputDelta, and feed entries. OAK removes terminal control sequences. It only reads the output file named by that session’s task. Local reads use file watches with a two-second fallback; saved-machine reads run there over SSH, at least ten seconds apart. Codex exec sessions have no recorded output file; their output updates with recorded exec and write_stdin results.
oak conversation --session <id> [--limit N] [--since <cursor>] [--machine <label>] --jsonRead the native transcript as renderer-ready updates. --limit is the last N turns of an initial read, 50 by default, and truncated reports the bytes cut above them. --since continues from the byte cursor the previous read returned; reset means the transcript was replaced, so redraw rather than append. Clients without a captured-store checkpoint can request --with-source and return its opaque source as --source <token> with the next cursor to detect replacement across processes.
oak machine add <label> <ssh-target>Provision and register a herdr machine.
oak machine list --jsonList saved machines.
oak sync now · oak sync plan · oak sync statusShare Claude Code sessions, memory, plans, skills, agents and commands, Codex rollouts and OAK's own store with the saved machines: text on every machine, merged three ways; sessions on the machine that made them and the backup. Each machine a run asks catches its local database up first, so its record log holds what it has done. plan previews a run and copies nothing; status shows the last run and open conflicts. Database & sync explains what each machine keeps; Sync across machines is the reference.
oak sync fetch <session>Bring one session here from the machine that made it, or the backup.
oak sync resolve <conflict>Keep this machine's file: move the other machine's copy to sync's trash and close the conflict now. oak sync status lists each conflict's id; the terminal app's i list, VS Code's Timeline and JetBrains' Sessions tab offer it as deleting the copy.
oak sync setupChoose where sessions are backed up (none, a saved machine, or an encrypted folder), make or bring the folder's key, and preview a first run. It asks on a terminal; --none, --machine <label> or --folder <path> otherwise. A machine reinstalled takes over its record in the folder, which no run restores from or writes until then: setup asks on a terminal, and --restore says so otherwise.
oak sync backup · include · exclude · familyChoose the backup (a saved machine, or --folder <path>: a share, a NAS or a disk, encrypted on each machine with a key the folder never holds), the machines and projects to sync, and where each kind of file is kept.
oak sync keyThe backup folder's key here: its fingerprint; --show prints it for a password manager, --import takes one on standard input or at a prompt that shows nothing (never as an argument), --from <machine> copies one over SSH.
oak sessions [--json] [--all]List this machine’s conversations, grouped by workspace with the current workspace first. Rows include the title, edit count, tokens, duration, model and last activity. Editor windows use the CLI on their workspace host; mirrored transcripts, bridge pointers without a local conversation, sessions in which nothing happened, and Codex Auto-review threads are excluded. --all also lists the Auto-review threads, and --session <id> lists the one it names.
oak <verb> … --machine <label>Run views, review, list, sessions, conversation, feed, processes, multitask, subagents, diff, keep, undo, redo, resolve, clean, task-keep, task-undo, task-clear, chat-context, comment, quote, ignore or search on a saved machine over SSH, where the session's store and files are, with that machine's own oak, in the session's own workspace there (sessions --json and search are answered from that machine's records here instead while oak sync keeps them current, saying so). Program output and exit status come back unchanged (output printed to a terminal is filtered, as the CLI's own is); transport failures are named. The terminal Review tab, including --once, and Observatory conversations use it for a session on another machine. OAK_MACHINE_TIMEOUT_MS overrides the 120-second overall deadline. Remote conversations, unit expansion, comment mark-sent and ignore --dry-run require a compatible remote CLI and fail before acting if it is too old.
oak doctor --fixRepair herdr (binary, integrations, plugin, missing sidebar widths and the gruvbox theme when no theme name is set), PTY helper permissions and outdated focus servers.
oak focus --session <id> --tab observatoryNavigate an attached OAK terminal.
oak demo --fastProduce a demo session to explore: an isolated demo-* session and an observatory-demo/ folder in the current directory, both removed by oak demo --clean.
oak modelsList the local Ollama models and the one Codex runs; oak models use <name> switches Codex to one.
oak ignore --check <path>Explain a .observatoryignore decision.
oak store · oak cleanLocate the store; reap stale session data.
oak sessions --delete <id> · --undelete <id>Hide a session from OAK and purge its captured edits; the transcript itself is not deleted. --undelete lists the session again, without the purged edits, unless the backup folder of oak sync keeps a copy of them, which the next oak sync now brings back. Pending edits are purged only with --force.
oak update · oak version --checkUpdate everything OAK installed, on this machine and on each saved machine (--here: this machine only), except a project's own .claude/settings.json, which gets a row naming the oak init --repair to run there, a CLI linked to a source checkout, whose row names the checkout to update, the copy oak machine add pushed, whose row names the oak machine add that updates it, and a local build (a version ending in -dev.0), which --force or --channel replaces; check for a newer release.
💡
Every command is a data source

Add --json to nearly any command for its raw payload. This is exactly what the editor extensions consume — which is why a number in VS Code, in JetBrains, and on the CLI is always the same number.

ℹ
Run oak help for the full list

This page covers the commands you'll reach for; oak help lists every user-facing command with its main flags, and oak <command> --help prints the same list.

oak diff --ids <id,id,…> --json [--contents] [--preview-lines 50] reads a page of one to ten edits in the requested order. It returns records, statuses, line counts and preview patches; --contents adds before/after previews. Omitted lines are named. A zero preview budget requests full contents. The same bounded page runs on the saved machine with --machine and its usual deadline. diff --pending --json [--prompt <id>] [--offset N] returns the pending scope’s ids and one page together, excluding cancelled chains.

oak diff --ids <id,id,…> --patch returns patches, each edit’s patch exactly as oak diff <id> --patch prints it, keyed by id, with no page limit. An edit that cannot be read is named in errors and the others still come back. oak multitask --json --only-session --session <id> returns only that session’s own row, its workers and tasks, rather than every agent across the repository’s worktrees. The terminal app reads a saved machine’s previews and Workers these two ways, one SSH call each.

oak diff <id> --json returns session, id, file and an uncoloured patch. The same contract applies with --machine.

oak feed --kind agent --id <worker> [--session <parent>] --follow follows a worker’s own log and exits at its recorded end, with the exact UTC time. Add --machine <label> to poll its saved machine over SSH every ten seconds, or --json for one snapshot per line. See Worker logs.

oak usage --json keeps its unprefixed fields, such as monthCost and weekTokens, scoped to the active or requested session’s provider. usageFrom explicitly names that provider: claude or codex. For both accounts together, use claudeAccount and the claude*/gpt* fields; selecting a Codex session does not turn monthCost into Claude’s figure. claudeUsageFreshness and gptUsageFreshness give the peer record stamps shown in usage tooltips, including stale, failed and partial pulls.
