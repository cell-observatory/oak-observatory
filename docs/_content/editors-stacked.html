Reviewing edits one file at a time is right when you want to weigh each on its own. Sometimes you want the whole change in front of you instead. Open all in editor — from the Traces sidebar or the review toolbar — reads every pending review unit in one tab, ten changes per page: each edit's diff stacked below the last, each still carrying its own Keep and Undo.

Net diffs, not raw history

Each block is the unit's net change — repeated revisions of the same lines are already collapsed into one review unit, so a line the agent rewrote five times appears once, in its final form. Small reviews use the native viewer in JetBrains; large reviews use compact previews with added and removed lines coloured. The block header names the file, the edit number, and its +A −R churn; the diff below is the agent's own.

Decide at any scope

The verbs work exactly as they do everywhere else, gathered into one view. Keep or Undo on a block resolves that one unit and leaves the rest standing; the Review toolbar's Keep all / Undo all resolve the whole pending scope at once. A decided block keeps its verdict and offers Revert or Redo. A resolved block drops out of the pending set — reflected immediately in the Traces sidebar and the Overview's counts.

🔬
When a unit is a wall

A single unit that rewrote thousands of lines is a wall in any stacked view. OAK bounds each block to a readable window and marks where it was cut, so one enormous edit can't bury the others below it.

Show 10 more and Previous 10 move through the original order. Only the current page's diffs stay loaded. The title keeps the complete change count; page controls name the remaining changes. VS Code's native side-by-side view opens a bounded set and names the remainder, available through the stacked tab's page controls.

For a saved machine, Open all stays in this window. Each page comes from that machine's records in one call, and its Keep, Undo and Redo actions run there. Removed worktrees and missing files do not prevent review. The side-by-side view uses verified mounted files when available, with recorded before/after as the fallback. Opening a file to edit can still use Remote-SSH or Gateway.
