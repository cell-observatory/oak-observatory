The terminal app has three tabs: herdr · Observatory · Review (two, Observatory · Review, when it runs inside a herdr pane). Open it with oak to manage terminals, read conversations and decide captured edits.






  
  

  
  
  






Launching it


oak                 # the full dashboard
oak --tab review    # open on one tab: herdr, observatory or review
oak --session <id>  # pinned to one session
oak --once          # print one plain frame and exit (for a pipe or CI)
oak attach          # hand this terminal to herdr’s own client, with OAK in a pane



The tabs


  • herdr runs the terminal engine’s real client, including machines and agent permissions. Its own tab bar starts agents; OAK’s outer bar keeps the three fixed tabs.
    • 

  • Observatory joins live panes and unresolved history beside a pinned native conversation, with an explicit reply composer.
    • 

  • Review presents captured diffs and Keep / Undo decisions.


Keys


On Observatory, W opens the selected session’s workspace window in your GUI editor, one machine and workspace per press. The window pins that session, opens all pending changes stacked, reveals Review and Timeline, shows the grouped Overview and reuses one OAK terminal running oak, preserving your view placements. Groups naming one workspace also offer W window. The status row reports the command or explains why it cannot open.


Two options name your editors: Terminal editor (prefs.editor) and GUI editor (prefs.guiEditor). On Review, e or E opens the selection in the terminal editor and W opens it in the GUI editor, at the selected edit’s line; the key row reads e/E terminal editor · W GUI editor. A blank Terminal editor follows $VISUAL, then $EDITOR; a blank GUI editor is Auto, which picks one as the Observatory page describes.


Each tab has its key, named on the tab bar where the width allows: F1 herdr, F2 Observatory and F3 Review. They work from any tab and over any overlay, which closes first, as esc would close it; a box holding text you typed (the palette, the session picker’s or the help’s search, find in the diff, an options entry) closes too, and the text goes with it. A question waiting for your answer keeps them until you answer it. With shift, ctrl or alt an F-key is another key. A terminal that keeps an F-key for itself never sends it to OAK: in VS Code’s terminal F1 opens VS Code’s command palette, so there alt+1, Tab or a click on the tab bar reaches the herdr tab. On the Observatory and Review tabs, Tab and shift+Tab switch tabs too, as do ctrl+n/ctrl+p and alt+1–alt+3, and F4 onward focus their panes. On the herdr tab every other key belongs to the program or to herdr, ctrl+a included; OAK takes F1–F3 before herdr or the program sees them, unless herdr’s config binds the key. OAK listens on herdr’s own prefix (ctrl+b unless herdr’s config sets another, or each of the prefixes it lists): after it, m returns to the OAK tab you last used, M pins the focused pane’s session in Observatory and V opens Review on it, as long as herdr’s config leaves those keys unbound (herdr binds R itself, to reload its config); every other key after the prefix is herdr’s, and the prefix pressed twice still sends it to the program. Inside a herdr pane, as oak attach runs it, herdr is the host and keeps its prefix, there is no herdr tab, and OAK’s tabs switch with the plain keys above and F2 and F3. ctrl+q twice quits from any tab, or from OAK’s own tabs when herdr’s prefix is ctrl+q; pressed once on the herdr tab, it reaches the program when the two seconds OAK waits for the second have passed, or before the next key you press there.


No letter means one thing on one tab and another on the other. The keys both tabs share:


KeyAction

i / hEvery session waiting on you, the other machines’ that oak sync brought included / jump to the next one on this machine

For a session on another machine the count can arrive after you have moved on, to another question, into text you are typing or to the herdr tab: the refresh then drops nothing and says how many edits it kept (under another question, once you answer it), and r asks again


b · / · o · ?Choose a session, searching names and what was said in each · filter this tab · options · every key, read from your keymap




Options rebinds the verbs and refuses the keys the frame keeps for itself: Space, the digits, :, the mark keys and the Observatory’s own letters. Resetting every option asks first.


The rows at the bottom of every tab, the status row, the usage bar and the key row, copy like the text in a pane: drag across them with the left button and release it to copy what you selected to the clipboard. On the herdr tab nothing of that drag reaches herdr. The status row is cut at the terminal’s edge rather than wrapped, so a selection that starts in the status text and reaches the edge, or goes on past the row, copies the rest of the status as well; one that starts in a toast copies the toast as it shows. If those rows move before you release the button (the status row goes when its message does), nothing is copied. A click there does nothing.


A drag still held when the terminal changes size, in a pane or on the bottom rows, ends there and copies nothing. A toast on the status row says what each copy took, or why it took nothing, and goes after a few seconds.
