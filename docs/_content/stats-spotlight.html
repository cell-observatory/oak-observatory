Two surfaces answer "how much" and "how far along." Stats and Metrics quantify a session; Spotlight makes a single change legible inside a heavily edited file.

Stats

Stats reports the session's vitals and usage: the model and reasoning effort it runs on, cumulative tokens split into input, output, and cached, compaction history, and its own and with-agents token totals. For a session that started agents, the tokens show twice, each labelled: its own, and with every agent it started (see How a session counts the agents it started). For a session on a saved machine, these totals and the model are read there with --machine, under that machine’s name. An unavailable read leaves the session figures unknown; it never substitutes the local session’s totals. The review scoreboard describes the selected session; remote review is available in the Overview and Timeline. The Today / 7 days / 30 days token chart and the account usage sections count the database’s deduplicated usage across machines. The context window and session details belong to the selected session. When the database is unavailable, history is labelled as this machine alone. Selecting a remote session does not move either account section to that machine.

Metrics

Metrics reports derived numbers: line deltas, action and error counts, per-subagent duration and tokens, and tool latency. In short — Stats describes consumption; Metrics describes activity.

Dollar figures are estimates, not a bill

The Stats $ row, the month's figure on the status bars and oak usage --breakdown price a session's token counts at today's public API list prices, and a ~ marks each such figure. A subscription is not billed per token, so none of them is a bill. On a plan with no rolling windows, such as pay-as-you-go API use, the status bars show the spend Claude Code reported for the month instead, with no ~. Dollar estimates describes how each model is priced.

Spotlight

Spotlight dims every line the agent did not change, so the changes read at full contrast in a heavily edited file. It answers "what actually moved here" at a glance when a diff is buried in a large file.

The terminal and editor status bars omit the five-hour window; Stats, oak usage and the Claude Code status line retain it when the account has that limit. In every status bar the mo reset is followed by the month’s dollar figure. A ~ marks an estimate at OAK’s list prices; an actual charge has no tilde. A session’s usage distinguishes its own tokens from its total with agents. Five-minute and one-hour cache writes are priced separately, and a new price-table version reprices older messages in the database.

GPT’s month tokens, cache reads and estimated dollars include every machine whose usage the database holds, even after rollout files are deleted. Its budget uses the same machines’ weekly tokens. Hover the terminal app’s usage row or an editor’s status bar to see which machines the estimates include and the record stamp for each peer. Stale, failed and partial pulls are marked; Stats shows the same stamps. With the same messages, account readings and bill day, every machine computes the same month and week figures, even when transcripts have been copied between machines. oak usage --bill-day N and oak usage --gpt-bill-day N set each account’s bill day once: saved machines receive the setting with usage records and sync. The latest explicit setting wins; ties use the machine identifier. Set 0 for calendar months. Usage pulls run without sync setup, at most every five minutes while a usage reader is active. An offline machine keeps its last setting until the next successful exchange.
