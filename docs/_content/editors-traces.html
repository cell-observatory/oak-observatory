The Observatory Traces sidebar is the review surface that lives in the editor's own view column — a tree of every pending edit, grouped by the file it touched, with the decision verbs on every row. It carries the same review the terminal app does, rendered as a tree beside your files rather than a dashboard.

Grouped by file

Every row is one review unit — one piece of code, however many times the agent revised it — filed under its path. A file header carries that file's pending count and its own ✓ file / ✗ file actions, so a whole file can be accepted or reverted without opening it. Each unit beneath shows its +A −R churn and its per-unit ✓ / ✗.

Filter and sort

The header carries inline controls: a search field (a substring, or a regular expression the moment the text carries regex syntax), a filter dropdown for the file-type buckets and extensions — Code, Tests, Config, Docs, Styles, Other — and a sort dropdown (four orders — newest, oldest, name A→Z, name Z→A). The filter names what it is narrowing by and the sort names the order. Each file header also shows the exact time it last changed. A filter only changes what the tree shows, never a decision or the store.

Act on one, a file, or everything

The actions above the tree scope by size. Open all in editor reads the whole pending set as one stacked diff; Keep all and Undo all resolve the entire list at once. Keep and Undo on a unit, or ✓ file / ✗ file on a header, act at exactly that scope — and every one is guarded, so an edit a sibling is still touching is protected.

Resolved rows stay visible

Resolving a unit doesn't erase it: a kept or reverted row greys out in place with a redo/undo affordance, so a decision is reversible and the history stays legible. Revision chains that net to nothing — an edit the agent wrote then took back — fold into a cancelled-out footer you can dismiss. The sidebar never asks you to review code that no longer exists.

ℹ
One review surface, three places

The tree, the inline review over the code, and the terminal app's review tab are the same decisions on the same store. Resolve a unit in any one and it shows resolved in the others.

Review a session on another machine

Select a session from a saved machine (oak machine list --json). Open all in editor opens a stacked review in this window, ten changes per page. Each page is read in one bounded call to the saved machine; Keep, Undo and Redo run there and refresh the block. A file that no longer exists still shows its recorded change. The side-by-side switch uses a verified mount when available and the recorded before/after otherwise. Open on <machine> and the filename first use a matching mounted share for editing. OAK matches Linux or macOS mount tables against the saved host, its home share, or a network share mounted on both machines. A local file with the same pathname is not enough. The mounted files are editable, with highlights, inline review controls and File History. Keep, Undo, Redo and Resolve still run with --machine; OAK refreshes after each action because SMB notifications can lag.

Without a matching mount, VS Code and Cursor open a new Remote-SSH window at the session’s workspace, using the saved machine’s SSH target. JetBrains uses Gateway / Remote Development over SSH. OAK writes a request on that machine, valid for ten minutes and consumed once by the remote editor, to select the session and open the edit or file. The remote window uses its real files and normal OAK highlights, inlays and Open all view.

If OAK is missing on the remote editor server, the editor offers to run oak install-extensions --machine <label> there. Connect once first if the editor has not installed its server. JetBrains needs an installed remote IDE to build its documented Gateway connect link; if it cannot build the link, or Gateway does not open, the dialog gives the SSH target, workspace and steps for File → Remote Development → SSH → New Connection. After an expired request, select the session in that window’s OAK.

This window still lists remote edits, prompt scopes, counts and history, and runs review actions on their machine. Diff is a separate action: it opens the editor’s before/after viewer using contents read from that machine, with a patch fallback for older CLI versions. Replies remain in Timeline/Feed, quotes and review comments; Review has no reply box.

Remote tasks, search, navigation and replies

Task Keep, Undo, Clear and Clear Completed run on the selected machine through task-keep, task-undo and task-clear --machine. A failed remote action reports its reason and never falls back to a local task.

Search Conversations searches this machine and enabled saved machines concurrently, with the shared 45-second remote deadline and five seconds for the CLI to return. Each hit names its machine; opening it reviews the session there. Results from machines that answered remain available when another fails, with that failure named.

Keyboard review walks remote display units using the same mount-first, then SSH route. Press Ctrl+Alt+X (Cmd+Alt+X on macOS), then N/P for next/previous edit or Right/Left for next/previous file. With Reveal Next on Resolve enabled, a single Keep or Undo continues after a fresh read confirms the change was resolved.

Reply from Timeline/Feed, quotes or review comments. Review has no reply box.
